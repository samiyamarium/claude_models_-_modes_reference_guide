Claude Models & Thinking Modes

A quick study guide: which model to pick, what it costs you in speed, where it fits, and how Claude's reasoning and research modes work. Key exam terms are in the glossary at the end.

Models available

Anthropic organises Claude into tiers. Larger tiers reason better; smaller tiers answer faster and cost less per token.

Choosing a model

Match the model to the task, then optimise for latency and cost.

NeedStart withWhy
Real-time, high volumeHaikuLowest latency and cost per token
Balanced daily workSonnetBest quality-to-cost ratio
Complex reasoningOpusStronger multi-step reasoning
Hardest problemsFable / Mythos tierHighest capability

Rule of thumb: model size trades intelligence against speed and price. Many production systems use an orchestrator-worker pattern: a larger model plans, smaller models execute.

Thinking and research modes

These control how much Claude reasons or looks up before answering. More effort usually means better answers on hard tasks but higher latency and token use.

Standard response

Claude answers directly from training knowledge and the conversation. Fastest option.

Use for: simple Q&A, drafting, summaries, casual chat.

Extended thinking

Claude reasons step by step in a visible thinking block before the final reply. In the API it is enabled with a thinking parameter and a budget_tokens limit; thinking tokens are billed as output tokens. Newer models can also adapt how much they think to task difficulty (adaptive thinking).

Timing: slower, scales with budget. Use for: maths, logic, debugging, planning, multi-step analysis.

Web search

Claude fetches current information from the web and cites sources. Reduces dependence on the knowledge cutoff.

Timing: a few seconds per search. Use for: news, prices, current facts, anything that changes over time.

Research (deep research)

An agentic mode: Claude plans, runs many searches, reads sources, cross-checks and writes a cited report. It can also draw on connected tools and files.

Timing: slowest, minutes rather than seconds. Use for: market scans, literature reviews, competitor analysis, long cited briefs.

Tool use, connectors and MCP

Claude calls external tools (APIs, files, apps) through function calling. The Model Context Protocol (MCP) is an open standard for connecting Claude to data sources and services.

Use for: agents that act on email, calendars, code repos, databases.

Key terms glossary

Terms worth knowing for certification-style questions.

Context window
Maximum tokens Claude can consider in one request, input plus output.
Token
Unit of text processed and billed; roughly three-quarters of a word.
Latency
Time until a response begins or completes.
Knowledge cutoff
Date after which training data ends; web search fills the gap.
System prompt
Instructions that set role, tone and rules for a conversation.
Prompt engineering
Clear instructions, examples, step-by-step reasoning, XML tags, format limits.
Temperature
Controls randomness; lower is more deterministic.
max_tokens
Cap on tokens generated in a reply.
Chain of thought
Reasoning step by step; extended thinking builds it in.
budget_tokens
Maximum tokens allowed for extended thinking.
Tool use / function calling
Claude requests actions from external functions.
MCP
Model Context Protocol, a standard for connecting tools and data.
Agent
Claude working in a loop with tools toward a goal.
Multimodal
Accepts text, images and PDFs as input.
RAG
Retrieval-augmented generation: fetch documents, then answer from them.
Hallucination
Confident but incorrect output; reduce with grounding and citations.
Prompt caching
Reuse repeated prompt prefixes to cut cost and latency.
Batch processing
Asynchronous bulk requests at lower cost.
Safety / alignment
Anthropic's focus on helpful, honest and harmless behaviour.
Skills
Folders of instructions that teach Claude repeatable tasks.
